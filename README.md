# MikroTik: сеть офиса с нуля

Портфолио-проект на основе реальной практики системного администратора.
Описание проекта: Построение и настройка офисной сети на базе MikroTik: VLAN-сегментация, резервирование интернет-канала, VPN для удалённого доступа и связи между офисами, а также автоматическое резервное копирование конфигурации.

## Задача

3 этажа, ~60 рабочих мест, 7 серверов. 
- прокладка LAN-кабеля, 
- разводка по этажам, сегментация сети, 
- резервирование интернет-канала, 
- VPN для удалённых сотрудников и между офисами, 
- автоматизация бэкапов.


## VLAN — зачем

Один физический порт обычно передаёт трафик только одной подсети. У меня было несколько подсетей (20, 30, 40, 50), и все они должны были ходить через один и тот же кабель между роутером и свитчем.
Решение — VLAN: тегирование пакетов номером VLAN позволяет гонять несколько подсетей через один trunk-порт одновременно


## Разделение подсетей — как и почему

Подсети разделены **по отделам**. Потому что: изоляция трафика между отделами (одному отделу не нужно видеть трафик/ресурсы другого) и удобный учёт — сразу понятно, какой хост к какому отделу относится, по одному взгляду на IP.

| VLAN | Назначение | Подсеть |
|------|------------|---------|
| 99   | Управление/сервисная сеть (доступ к оборудованию) | 192.168.99.0/24 |
| 200  | Общая пользовательская подсеть (несколько этажей/свитчей) | 192.168.20.0/24 |
| 300  | Бухгалтерская подсеть | 192.168.30.0/24 |
| 400  | АУП-подсеть + Wi-Fi | 192.168.40.0/24 |
| 500  | Серверная подсеть (7 серверов) | 192.168.50.0/24 |


## Резервирование канала — как и почему

Для обеспечения бесперебойного доступа в интернет в офисе настроено резервирование интернет-соединения.
К маршрутизатору MikroTik подключены два независимых интернет-провайдера:
Основной канал — используется в штатном режиме.
Резервный канал — автоматически подключается при отсутствии интернет-соединения через основного провайдера.
Переключение между каналами происходит автоматически, без участия администратора. После восстановления основного интернет-соединения маршрутизация возвращается на основной канал.

- Основной маршрут — меньший `distance`, используется по умолчанию
- Резервный маршрут — больший `distance`, изначально выключен
- `Netwatch` пингует контрольный узел строго через основной канал; если узел перестаёт отвечать — включает резервный маршрут, при восстановлении связи — выключает обратно

## VPN L2TP/IPsec — почему и как

Для удалённых сотрудников настроен доступ к внутренней инфраструктуре офиса, включая общие сетевые папки и тестовый локальный сервер (ИБС).
Доступ осуществляется через защищённое подключение к офисной сети, что позволяет сотрудникам работать с внутренними ресурсами из-за пределов офиса
Для этого — L2TP/IPsec: L2TP встроен в Windows «из коробки» (не нужно ничего доустанавливать на компьютер сотрудника), IPsec поверх него закрывает главный минус L2TP — отсутствие шифрования.

## VPN между офисами (site-to-site) — почему и как

Удалённый офис (филиал) тоже должен был иметь доступ к общим папкам и тестовому локальному серверу (ИБС) головного офиса.
Для этого — site-to-site VPN между двумя MikroTik: SSTP (работает поверх TCP/443, легко проходит через firewall на удалённой площадке) + аутентификация по сертификатам.


## Автобэкап с отправкой на почту — зачем

Скрипт на роутере раз в неделю (через `Scheduler`) сам создаёт полный бэкап конфигурации и текстовый экспорт (`.rsc`), удаляет старые файлы бэкапов и отправляет оба на почту отдельными письмами. 
Если оборудование выйдет из строя — конфигурация не потеряна и лежит не только на самом роутере, но и в почте. Конфиг: `configs/08-backup-to-email.rsc`.
